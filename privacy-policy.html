隐私政策 · Microsoft Store 分发的版本同样适用这一页 Privacy Policy · applies to the Microsoft Store build as well

你的数据，只在你设备上。 Your data,on your device only.

这是一份正式的隐私政策，也是一份说明书：数据放在哪、什么会离开你的设备、什么时候离开、你怎样把它收回来。没有账号，没有埋点，没有一处是你读不懂的。

This is a formal privacy policy written as a manual instead: where your data lives, what leaves your device, when it leaves, and how you take it back. No account, no analytics, nothing you have to re-read twice.

01

适用范围

Scope

Bit Jarvis 包含桌面端（Windows / macOS / Linux）与移动端（iOS / Android），由个人开发者独立开发与维护，联系主体见第 11 节。本政策适用于所有发行渠道的版本，包括通过 Microsoft Store 分发的 Windows 版。桌面端以 Apache 2.0、移动端以 GPLv3 开源，你可以把这一页的每一句话拿去和代码逐行对照。

Bit Jarvis ships as a desktop app (Windows / macOS / Linux) and a mobile app (iOS / Android), built and maintained by an individual developer (see section 11). This policy covers every distribution channel, including the Windows build distributed through the Microsoft Store. The desktop app is Apache 2.0 and the mobile app is GPLv3: every sentence on this page can be checked against the source.

02

数据放在哪里

Where your data lives

留在你设备上的：对话与记忆、你打开或编辑的文件、你主动截取的屏幕内容、脚本与命令的输出、运行日志、以及你填写的模型凭据。这些默认不离开你的机器。

Stays on your device: conversations and memory, the files you open or edit, screenshots you take deliberately, script and command output, runtime logs, and the model credentials you enter. By default none of it leaves your machine.

会离开你设备的：只有两类。一是你发出的 prompt 与对话，当所用模型运行在云端时；二是你显式启用的跨端接力消息。除此之外我们不接收任何东西。应用没有账号体系，我们手上也没有用户表；服务器侧唯一留下的，是免费模型网关为额度核算登记的一个设备身份，细节见第 04 节。

Leaves your device: only two things. The prompts and conversations you send, when the model you are using runs in the cloud; and the handoff messages you explicitly enable. Nothing else reaches us. There is no account system and no user table; the only thing left on our side is the device identity the free-model gateway registers for quota accounting, detailed in section 04.

数据目录：Windows 为 %USERPROFILE%\.jarvis，macOS / Linux 为 ~/.jarvis。它不用系统隐藏目录，就是为了让你随时能打开看一眼。
Data directory: %USERPROFILE%\.jarvis on Windows, ~/.jarvis on macOS / Linux. It is deliberately not buried in a hidden system folder, so you can open it and look whenever you want.
03

我们不收集什么

What we do not collect

  • 不做行为埋点，不上传运行日志或崩溃报告；免费模型的额度核算只记调用用量，不含对话内容
  • 不把你的对话用于训练；内置免费模型的调用同样不进入训练流程
  • 不建立应用账号，不收集邮箱、手机号、通讯录或广告标识；设备侧唯一的标识是网关用于额度核算的 install_id（见第 04 节）
  • 不追踪位置、通讯录、相册；除非你在系统设置里显式授权
  • 不接广告 SDK，不做数据交易，不向第三方出售任何数据
  • No behavioural tracking, no log or crash upload; free-model quotas count usage only, never conversation content
  • No training on your conversations; calls to the built-in free models are not routed into training either
  • No app accounts, no email, no phone number, no contacts, no advertising identifiers; the one device-side identifier is the install_id the gateway uses for quotas (see section 04)
  • No location, contacts or photo tracking, unless you grant it in the OS
  • No ad SDKs, no data brokering, no selling data to third parties
04

会离开设备的数据与去向

Data that leaves the device, and where it goes

内置免费模型网关自建服务
送出你的 prompt 与对话，经我们自建的网关转发给上游模型。仅在你选用内置免费模型时发生。网关持有上游模型的凭据并负责路由，你不需要提供任何 key。首次使用会登记一个设备身份（install_id、平台、应用版本、设备信息哈希），换回的 device_id 与令牌只用于额度核算；额度用量留在网关侧，本机内保存的那一份随数据目录一起删除。
你配置的模型提供方BYOK
送出你的 prompt 与对话，直达提供方，不经我们的服务器。对方如何处理与保留，取决于该提供方的条款，我们无权也无能力删除。用 Ollama 时流量不出本机回环地址。
Jarvis IM默认关闭
送出跨端接力的消息。走我们自建的 Matrix homeserver（bitjarvis.chat），协议与代码开源（AGPL-3.0）。不启用即不发生。
GitHub Releases非商店版
送出一次版本查询请求，用于检查更新。不携带你的对话、文件或标识信息。商店版由商店负责更新，不发起这类请求。
Microsoft Store商店版
安装与更新过程中的信息由 Microsoft 处理，适用 Microsoft 隐私声明。我们不接触这些数据，也无从获取。
系统原生服务按需授权
文件、通知、麦克风、摄像头等能力，访问前都要经过系统权限弹窗或应用内的确认，撤回授权即刻失效。
Built-in free-model gatewayself-hosted
Sends your prompt and conversation through our own gateway to the upstream model. Only when you pick a built-in free model. The gateway holds the upstream credentials and handles routing; you supply no key. First use registers a device identity (install_id, platform, app version, a device-info hash); the device_id and token it returns serve quota accounting only. Quota usage stays on the gateway side, and the local copy disappears with the data directory.
The model provider you configureBYOK
Sends your prompt and conversation straight to the provider, never through our servers. How it is retained and used is governed by that provider's terms; we cannot see or delete it. With Ollama, traffic stays on the loopback interface.
Jarvis IMoff by default
Sends cross-device handoff messages through our self-hosted Matrix homeserver (bitjarvis.chat); protocol and code are open (AGPL-3.0). Does not happen unless you turn it on.
GitHub Releasesnon-Store builds
Sends one version query to check for updates. It carries no conversation, file or identifier. Store builds are updated by the Store and make no such request.
Microsoft StoreStore build
Install and update information is handled by Microsoft under the Microsoft Privacy Statement. We neither touch nor receive it.
OS-native servicesgranted per use
Files, notifications, microphone, camera: every access goes through an OS permission dialog or an in-app confirmation, and revoking it takes effect immediately.
05

商店版的额外说明

Notes on the Microsoft Store build

  • 完全信任应用：商店包声明 runFullTrust，以你的用户身份运行，不受 AppContainer 隔离。这是它能替你操作本地文件、运行本地脚本的前提，也意味着它的权限与你自己登录的账户一致。
  • 更新由商店交付：商店版不使用应用内自更新通道。任何代码变更都必须重新提交、由 Microsoft 重新签名后经商店下发，我们无法静默替换你机器上的代码。
  • 签名：商店版的安装包由 Microsoft 签名，第三方无法伪造一个看起来相同的安装来源。
  • 与直装版的关系：从官网或 GitHub 下载的安装包与商店版是同一套程序，数据目录与数据流向一致，本政策对两者同等适用。
  • Full-trust app: the Store package declares runFullTrust and runs as your user, outside AppContainer isolation. That is what lets it work on your local files and run local scripts, and it also means its privileges match your own signed-in account.
  • Updates come from the Store: the Store build does not use an in-app self-update channel. Any code change requires a fresh submission, re-signed by Microsoft and delivered by the Store. We cannot silently replace code on your machine.
  • Signing: the Store package is signed by Microsoft, so no third party can forge an install source that looks the same.
  • Relative to the direct download: the installer from our site or GitHub is the same program as the Store build, with the same data directory and the same data flows. This policy applies to both.
06

保留与删除

Retention and deletion

  • 桌面端：数据一直留在数据目录里，直到你删掉它。卸载应用不会删除这个目录。彻底清除的步骤：退出应用 → 删除 %USERPROFILE%\.jarvis（Windows）或 ~/.jarvis（macOS / Linux）。
  • 移动端：数据在应用沙盒内，卸载即清除。
  • 凭据：你自己填写的 API key 保存在上述数据目录中，删除目录即删除凭据。
  • 迁移备份：应用在改写 provider catalog 之前会留一份副本，用于回滚，副本里含同样的凭据。这类副本 90 天后自动清理，且仅在确认在用的目录仍完好可读时才清理（若不可读则一律保留），每次保留或清理都有日志可查。
  • 跨端接力：若你启用了 Jarvis IM，消息会经过自建 homeserver。关闭该功能会停止后续同步；如需清除服务端已有内容，按第 11 节联系我们。
  • BYOK 直连：你的 prompt 到达模型提供方之后的保留策略由对方决定，我们无权删除。
  • Desktop: data stays in the data directory until you delete it. Uninstalling the app does not remove it. To erase everything: quit the app, then delete %USERPROFILE%\.jarvis (Windows) or ~/.jarvis (macOS / Linux).
  • Mobile: data lives inside the app sandbox and is wiped on uninstall.
  • Credentials: API keys you enter are stored in that same data directory; deleting it deletes them.
  • Migration backups: before rewriting the provider catalog the app keeps a copy so a rollback is possible, and those copies hold the same credentials. They are auto-removed after 90 days, and only once the live directory is confirmed readable and populated; if it is not, every copy is kept regardless of age. Each keep-or-remove decision is logged.
  • Handoff: if you enabled Jarvis IM, messages pass through our self-hosted homeserver. Turning the feature off stops further sync; to clear what is already on the server, contact us via section 11.
  • BYOK direct: once your prompt reaches the model provider, retention is governed by that provider. We cannot delete it.

儿童

Children

本应用不面向 13 周岁以下儿童，我们不会有意收集儿童的个人信息。应用不设账号体系，也不收集可用于识别年龄或身份的信息；如果监护人认为有儿童信息被留存，可以按第 11 节联系我们，我们会协助清除本地与服务器上的相关数据。

The app is not directed to children under 13, and we do not knowingly collect personal information from children. There is no account system and no age- or identity-identifying data is collected. If a guardian believes a child's information has been retained, contact us via section 11 and we will help remove it from local and server storage.

安全与已知边界

Security and known limits

  • 先问再做：写文件、执行命令、发起网络请求、访问私人目录，每一步敏感操作都要你确认。这是隐私承诺能被真正执行的前提。
  • 两层防护：应用层的 PathGuard 四级访问控制，加上系统级沙盒（macOS Seatbelt / Linux Bubblewrap / Windows Restricted Token）。
  • 已知边界写在明面上：Windows 上无法使用 POSIX 权限位，凭据以明文文件保存在数据目录中，同一账户下的其他程序仍可能读取。这些写进了仓库的 SECURITY.md，我们选择公开而非隐瞒。
  • 商店版是完全信任应用，其运行权限与你登录的账户一致，请像对待任何本地开发工具一样对待它。
  • Ask first: writing files, running commands, making network calls, reaching into private folders. Every sensitive step asks for your confirmation. That is what makes the promise enforceable.
  • Two layers: application-level PathGuard four-tier access control, plus an OS-level sandbox (macOS Seatbelt / Linux Bubblewrap / Windows Restricted Token).
  • Known limits, stated openly: POSIX permission bits are unavailable on Windows, credentials are stored as plaintext files in the data directory, and other programs under the same account may still read them. This is documented in SECURITY.md in the repository rather than left unsaid.
  • The Store build is a full-trust app running with your account's privileges. Treat it the way you would treat any local developer tool.
09

你的权利

Your rights

访问、更正、导出、删除、撤回同意。因为绝大多数数据只存在你的设备上，这些权利你可以在自己的机器上直接行使：打开数据目录就是访问，复制它就是导出，删掉它就是删除，不需要向我们申请，也不必等待审批。

Access, correction, export, deletion, withdrawal of consent. Because almost all of your data lives on your own device, you exercise these directly: opening the data directory is access, copying it is export, deleting it is erasure. No request to us, no waiting for approval.

想停止数据离开设备，只需切换到本地模型（Ollama），或关闭跨端接力。想撤回某项系统权限，在系统设置里关掉对应授权即可立即生效。若你认为我们持有你的某些数据并希望处理，按第 11 节联系我们。

To stop data leaving the device, switch to a local model (Ollama) or turn off handoff. To withdraw an OS permission, revoke it in system settings and it stops immediately. If you believe we hold data of yours and want it handled, use section 11.

政策变更

Changes to this policy

只在真正变化时更新这一页。判断标准很具体：新增了必须离开设备的数据类型、更换了默认模型提供方或 IM homeserver、沙盒结构发生调整。每次变更都会更新顶部的日期，并在 GitHub release notes 里写明改了什么，不做静默修改。条款的重大变更会提前告知，不会追溯适用于你已经产生的数据。

This page changes only when something real changes: a new data type that must leave the device, a change of default model provider or IM homeserver, a restructuring of the sandbox. Every change updates the date at the top and is spelled out in the GitHub release notes. No silent edits, and material changes are announced in advance rather than applied retroactively to data you already produced.

Contact
