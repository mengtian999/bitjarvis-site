隐私政策 · 写给每一个把 Jarvis 打开的人

你的数据，只在你设备上。

这份说明写给每一个把 Jarvis 打开的人。它不是一份为合规写就的官样文章——它是我们和模型提供商之间，能替你守住的那条线，以及这条线之外你还能自己决定什么。

承诺

三条我们不会动摇的事

如果下面这三条任何一条不成立，这份政策就不成立。

01
🏠

本地优先

对话、记忆、文件、截图、脚本输出——都留在你自己的机器上。默认纯本地运行，不依赖任何云服务，也没有「注册账号」这步。

02
🔑

自带 + BYOK

装完就能用——我们自建的模型网关内置了几组免费模型，不需要你提供任何 key。也支持你自己的 API key（Anthropic / OpenAI / Google / Ollama / 任何 OpenAI 兼容端点），走 BYOK 时流量直达 provider，不经网关。

03
🔓

明文开源

桌面端 Apache 2.0，移动端 GPLv3。你可以一行一行看我们写了什么、读了什么、传了什么——审计的权利在你手上。

数据在哪里

桌面 · 手机

数据不是「存在云端某个角落」，是落在你明确知道的位置。

💻
桌面端
数据目录~/.jarvis（Windows 上为用户目录下的默认位置）
凭据存储明文文件，Owner-only 权限（macOS / Linux 生效；Windows 依赖 NTFS ACL，应用不做权限修改）
沙盒PathGuard 四级访问控制 + 操作系统级沙盒（Seatbelt / Bubblewrap / Restricted Token）
备份仅在数据迁移期间生成，超过 90 天自动清理，清理前校验主目录可读
网络出口内置的模型网关（含免费模型）+ 你配置的模型提供商端点（BYOK 模式）+ 可选的 IM homeserver
📱

数据目录iOS / Android 各自的 App 沙盒内，卸载即消失

不做的事

五条我们主动放弃的事

写「我们不做」比写「我们做」更难。因为前者意味着真的什么都不做。

  • 不埋点、不采集使用数据、不上传任何日志或崩溃报告
  • 不把对话内容作为训练数据（模型提供商的默认政策仍以其自身条款为准）
  • 不追踪位置、通讯录、相册——除非你在操作系统里主动给了权限
  • 不接广告 SDK、不做数据交易、不卖给任何第三方
  • 不设置强制注册、不索要邮箱、不发送推送营销邮件
第三方

我们不得不依赖的第三方

每一项都标了「传什么」和「为什么不传更多」。

Jarvis 模型网关（自建）免费模型的 prompt 与对话内置的免费模型走自建网关。你无需提供任何 key；网关在服务器端持有对应供应商的凭据并做路由。BYOK 模式下你的 prompt 直达你配置的 provider，不经过这个网关。
模型提供商你的 prompt 与对话你配置的 provider（Anthropic / OpenAI / Google / Ollama / 其他 OpenAI 兼容端点）。key 是你自己的，流量直达，我们不经手；Ollama 走 127.0.0.1 本机回环。
Jarvis IM（可选）IM 消息跨端接力时启用，走自建 Matrix homeserver（bitjarvis.chat）。协议与代码完全开源（AGPL-3.0）。不启用即不启用。
CloudKit角色元数据仅在 iOS 上，用于跨设备同步角色（名字 / 头像 / 说话风格）。不含会话内容、不含记忆、不含工具调用记录。关闭 iCloud 同步即停用。
操作系统原生服务你显式授权的资源健康、日历、联系人、HomeKit、蓝牙等。每一项访问都遵循操作系统的授权弹窗；权限收回即刻失效。
GitHub / TestFlight下载与 beta 分发的元数据仅在你主动 clone / 下载安装包时产生，不参与运行时数据流。
沙盒与安全

Agent 是工具，不是神

Agent 是工具，不是神。所以每一步敏感操作都设计成「先问你」——写文件、执行命令、网络请求、访问私域，都要你点头。这个「先问」的机制，是隐私承诺能被真正执行的前提。

桌面端有两层：应用层的 PathGuard 四级访问控制 + 操作系统级沙盒（macOS Seatbelt / Linux Bubblewrap / Windows Restricted Token）。移动端有一层：沙盒化的 Alpine Linux（iOS iSH / Android PRoot），Agent 装包跑脚本都在容器里，不越出 App 边界。

已知边界写在桌面端 SECURITY.md 里——比如 Windows 上无法用 POSIX 权限位、凭据以明文存储、同一用户账号下的其他程序仍能读。这些是我们主动告知、而非藏起来的。

变更与联系

这份政策什么时候改

只在真的发生变化时改：新增了必须传出的数据类型、更换了默认的模型提供商或 IM homeserver、沙盒结构发生调整。改动会在 GitHub release notes 中标注，不做静默更新。

有疑问？

我们没设置邮箱表单——因为一份好的隐私政策，应该像一份好的代码，可以直接对着仓库追问。
